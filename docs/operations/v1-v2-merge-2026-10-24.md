# V1 updates merged into SaaS V2 - 2026-10-24

Source: `v1` at `9b92202e9cc8861956341fc1cfca6f5c31a62351`.
SaaS baseline: `v2` at `cd1b6a9314d355af6aa2d4c6cf4ffbee674328c9`.

## Resulting changes

- Teacher attendance API writes match the course and date, validate an active,
  unfinished course in the actor's scope, and reject overwriting closed or
  archived days. Status is limited to `open` and `closed`.
- Attendance deletion confirmation correctly reaches its parent Livewire
  component. Closed days must be reopened before deletion.
- Offline attendance refreshes the page after the queued changes finish merging,
  while preserving records already submitted by another connected device.
- Backup restoration resumes the actor's session using the restored account's
  identity rather than assuming the old numeric ID still belongs to that user.
  Missing, empty, or truncated archives are excluded from usable recovery points,
  and the backup screen explains why they are unavailable. Restoration preserves
  the current installation's recovery-point history.
- Arabic labels align consistently across assessment results, teacher attendance,
  course-end final tests, and finance ledger PDFs.
- Livewire navigation reloads after a changed asset build. Modal/sidebar spacing
  and the finance header search styling are corrected.
- The phone-input fix already existed in V2; this merge does not change it.

## SaaS compatibility

The existing tenant hostname resolution, database/storage isolation, Platform
access, provisioning, subscriptions, backups, module permissions, and immutable
learning paths remain in place. No landlord models, landlord services, tenancy
configuration, or web/API route middleware are replaced by V1.

Teacher attendance remains usable without the Classes module. For these tenants,
the API requires callers to omit `course_id` and returns `course_id: null`.
Closed-day protection still applies.

The new `attendance:prune-courseless` task runs every minute. In V2 it enumerates
operational, provisioned tenants and enters each tenant's database/storage scope.
It deletes course-less teacher attendance days and their records only when that
tenant has both Classes and Teacher Attendance enabled. Tenants without Classes
retain their valid course-less attendance. Suspended/unprovisioned tenants and
the default application database are excluded. A failed tenant is reported without preventing the remaining tenants
from being processed, and the prior database/storage context is restored.

Use `php artisan attendance:prune-courseless --tenant=<slug>` to restrict an
intentional manual cleanup to one eligible tenant.

## Operational scope

This merge adds no database migrations or dependency changes. It does not run the
cleanup against application data, deploy code, or change production databases.
Build the updated frontend and refresh the normal Laravel caches when deploying.
The scheduled cleanup begins when the merged code is deployed and the scheduler
runs, so account for removal of legacy course-less attendance in tenants that
have Classes enabled.

The merge is local on `v2`; no push is performed as part of this request.
