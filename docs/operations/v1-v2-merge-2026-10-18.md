## Merge behavior

V1 contains `e5ec17d5`, the historical rollback of the SaaS implementation for
the single-tenant release. Reapplying that rollback to V2 would remove tenant
and Platform functionality. This merge keeps the V2 foundation and integrates
the V1 changes after that rollback, while recording both branch tips as parents.

Tenant hostname resolution, database and storage boundaries, Platform access,
provisioning, backups, subscriptions, immutable learning paths, and module access
remain in place. The expanded mobile API also enforces tenant modules, storage
quotas, required password changes, and module-aware navigation and payloads.
Offline attendance checks the applicable tenant modules before writing a batch.
Legacy invoices still require one student owner before write operations.

The Postman collection includes both the tenant capabilities endpoint and manual
student points without enrollment. See [the mobile setup instructions](../postman/README.md)
for tenant hostname configuration.

## Deploying V2

Publication to Git does not deploy the running application. Take landlord and
tenant backups and use the normal maintenance procedure before applying the
three new tenant migrations:

- `2026_10_12_000000_add_completion_settings_snapshot_to_courses_table.php`
- `2026_10_13_000000_add_curriculum_days_per_week_to_courses.php`
- `2026_10_13_010000_track_past_memorization_saber_origin.php`

From a clean multi-tenant server checkout:

```bash
git switch v2
git pull --ff-only origin v2
composer install --no-dev --prefer-dist --optimize-autoloader
npm ci
npm run build
php artisan optimize:clear
php artisan migrate --database=landlord --path=database/migrations/landlord --force
php artisan saas:migrate-tenants
php artisan saas:rehearse-release --json
php artisan view:cache
php artisan queue:restart
git rev-parse HEAD
```

Compare the deployed SHA with the published merge commit. The rehearsal must
report no blockers before ending maintenance. Verify `/up`, Platform login,
tenant login, disabled-module access, and mobile authentication using the tenant
hostname. See the [SaaS runbook](saas-vps-runbook.md) for the full procedure.
